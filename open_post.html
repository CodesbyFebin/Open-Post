REA Reverse Engineering Specification

Deconstructing Postiz with morluto/rea principles into zero-bloat standalone software

1. System Deconstruction: Postiz vs Open Post

Applying REA's phase methodology: Decompile contracts, isolate domain logic from distributed infrastructure, and reconstruct a clean-room implementation.

Component Postiz (`postiz-app`) Open Post (`open-post`) REA Optimization Outcome
Workflow Orchestration Temporal Cluster (Heavy Java/Go server, gRPC workers, dedicated DB) Lightweight In-Process Event Loop + Cron Eliminated 1.5GB RAM and complex Temporal worker failure modes.
Queue Infrastructure Redis BullMQ instance Embedded SQLite / In-Memory queue Zero external queue dependencies. Zero Redis connection drops.
Storage & Database PostgreSQL + Prisma ORM + MinIO S3 Zero-Config SQLite / Local Storage Single self-contained data directory. 1-second migration.
Autopilot AI Loop CLI agent tool / Cloud SaaS wrappers Integrated Persona Engine + Ollama/OpenAI Autonomous topic banking, auto-cadence filling, 100% offline heuristic fallback.
License & Cost AGPLv3 with enterprise feature tiering Permissive MIT License 100% Free forever. Zero paywalls. No team seat limits.
